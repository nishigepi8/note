# 常用回复模板

在 GitHub/GitLab 进行 Code Review 或回复 Issue 时可使用的模板。

---

## 1. 批准合并 (Approval)

```
✅ 代码 review 通过。

- [ ] 代码逻辑正确
- [ ] 命名规范
- [ ] 无安全隐患

LGTM，可以合并。
```

---

## 2. 拒绝合并 (Request Changes)

```
⚠️ 需要修改后再提交：

1. [问题描述]
2. [问题描述]

请修复以上问题后重新提交。
```

---

## 3. 确认 Bug 存在

```
感谢报告！已确认这是一个有效的 Bug。

初步分析：[可能的原因]

优先级：[高/中/低]
负责人：@xxx
```

---

## 4. 关闭重复 Issue

```
感谢报告！这个 Issue 与 #xxx 重复，我会关闭此问题并在原 Issue 中跟进。

如有新信息，欢迎在 #xxx 中补充。
```

---

## 5. 需要更多信息

```
感谢报告！

为了更好地定位问题，请补充以下信息：

1. [环境信息]
2. [重现步骤]
3. [日志/截图]
```

---

## 6. 正在处理中

```
收到，正在处理中。

预计完成时间：
相关 PR：
```

---

## 7. 功能暂不接受

```
感谢你的建议！

经过讨论，目前暂时不计划实现此功能，因为：

1. [原因1]
2. [原因2]

后续如果计划有变会重新评估。感谢理解！
```

---

## 8. 合并冲突处理

```
⚠️ 存在合并冲突，请先解决冲突后再提交。

解决步骤：
1. `git checkout master`
2. `git pull`
3. `git checkout your-branch`
4. `git rebase master`
5. 解决冲突后 `git push --force-with-lease`

如有需要可以随时 @ 我。
```

---

## 9. 感谢贡献

```
🎉 感谢你的贡献！

代码已合并到 [分支]，将在 [时间] 部署到 [环境]。
```

---

## 10. 延迟处理

```
标记为 [冻结/待定]。

原因：[说明原因]
重新评估时间：[时间]
```

---
