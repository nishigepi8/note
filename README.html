01

我在写什么

技术文档不应该只是「配方」——照着做就能成功。更重要的是记录决策的过程： 为什么选这个方案，遇到什么问题，如果重新设计会改什么。

从 How 到 Why

早期关注具体实现与操作步骤；现在更关心设计理念、架构演进和技术本质。

记录决策过程

不只给结论，还写权衡：为什么是它而不是另一个，代价落在哪里。

建立技术体系

零散的知识点像拼图碎片，写作把脉络、模式和交叉点串成体系。
