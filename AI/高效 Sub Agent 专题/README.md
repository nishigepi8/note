# 高效 Sub Agent 专题

这个专题聚焦的不是“多几个 Agent 会不会更强”，而是一个更实际的问题：
**当任务开始变复杂时，怎样把 Agent 系统设计成一个可分工、可收敛、可复盘的协作系统**

对我来说，`Sub Agent` 的重点从来不是角色数量，而是三件事：

- 主代理如何拆职责
- 子代理之间如何传递必要信息
- 系统怎么判断应该继续迭代，还是及时停止

```mermaid
flowchart LR
    A[主任务] --> B[Supervisor 拆解]
    B --> C[生成子代理职责]
    C --> D[Blackboard 保存阶段结果]
    D --> E[Relay 定向传递]
    E --> F[Review 判断是否继续]
    F --> G[最终收敛输出]
```

## 这个专题重点讨论什么

这里不把 `Sub Agent` 写成抽象概念说明，而是聚焦工程上真正决定成败的部分：

1. 主代理如何做任务拆解，而不是把角色预先写死
2. 中间结果如何沉淀、传递和过滤，避免互相抄作业
3. 多轮协作如何设置停止条件，避免无限迭代
