# 单 Agent 输出样例

## 任务

> 设计一个本地 Ollama 多智能体系统，要能分析需求、给实现建议、检查冲突并输出最终结论。

## 典型输出

> 可以设计一个本地 Ollama 多智能体系统。整体上可以采用微服务架构，前端通过 Web 页面提交需求，后端使用 Python 或 Java 实现核心逻辑，AI 部分可以使用多个模型分别负责需求分析、技术建议、冲突检测和总结输出。
>
> 主要模块包括：
> 1. 需求分析模块：负责收集和整理需求。
> 2. 技术建议模块：负责选择技术栈并给出方案。
> 3. 冲突检测模块：负责识别潜在问题。
> 4. 总结模块：负责形成最终文档。
>
> 实现上可以使用 Flask、FastAPI 或 Spring Boot 作为服务入口，数据库可选 MySQL 或 PostgreSQL，向量能力可结合向量数据库。
>
> 总体来说，这个方案可行，后续可以继续补充测试、监控和权限管理。

## 问题

这类输出表面上完整，但常见问题是：

- 分析、实现、冲突、总结混在一起
- 没有明确依赖关系
- 没有真正的角色边界
- 没有中间协作过程
- 很容易重复说一遍同样的东西

如果任务复杂一点，单 Agent 的问题会更明显：它会一边讲架构，一边讲实现，一边讲总结，最后看起来像一份“什么都有，但什么都不够具体”的回答。
